위대한상상 (요기요) · AUTOMATION 05

요마트 재고입력 자동화

요마트 스테이징 매장에 재고를 넣으려면 백오피스의 여러 화면에서 설정을 확인하고, 토큰을 만들어 API를 직접 호출해야 했습니다. 이 과정을 Slack 모달 하나로 옮기고, 사전 조건 검사와 결과 알림까지 자동으로 처리하도록 만들었습니다.

  • SLACK BOLT
  • WORKFLOW BUILDER
  • JENKINS REMOTE TRIGGER
  • PYTHON
  • REST API
  • INPUT VALIDATION
AT A GLANCE

01 · INPUT

모달 하나로 입력합니다.

매장 vendorId, 상품코드·수량 배열, 스테이징 서버를 한 화면에서 입력합니다. 여러 상품의 재고를 한 번에 넣을 수 있습니다.

02 · PRECHECK

막히는 지점을 먼저 찾습니다.

API를 호출하기 전에 백오피스 사전 조건을 차례로 검사하고, 조건을 만족하지 않으면 해당 단계에서 멈춥니다.

03 · NOTIFY

고칠 곳까지 알려 줍니다.

실패하면 막힌 단계의 메시지와 수정할 백오피스 화면 링크를 Slack 채널로 함께 보냅니다.

- FLOW

입력부터 알림까지,
세 단계로.

Slack 봇이 입력값을 파라미터로 Jenkins 잡을 호출하고, Jenkins 잡이 Python 코드를 실행한 뒤 결과를 Slack 채널로 알립니다.

STEP 01 · SLACK BOT

입력과 검증

Slack 모달에서 입력값을 받고, 상품코드가 배열 형식인지 검증한 뒤 입력값을 파라미터로 Jenkins 잡을 호출합니다.

Bolt + Workflow Builder

STEP 02 · JENKINS JOB

스크립트 실행

외부에서 URL과 토큰으로 실행할 수 있도록 설정했고, 전달받은 파라미터로 Python 스크립트를 실행합니다. Jenkins에서 수동으로 실행할 수도 있습니다.

Remote Trigger · Parameterized Build

STEP 03 · SLACK CHANNEL

결과 알림

스크립트가 수행한 결과나 에러를 QE 자동화 채널로 알립니다.

Success · Fail + Link

- INPUT

실행 전에 걸러 냅니다.

- PRECHECK

API를 부르기 전에,
조건부터 확인합니다.

재고 API는 백오피스 설정이 하나라도 빠지면 실패합니다. 스크립트는 아래 순서로 조건을 검사하고, 실패하면 해당 단계의 메시지를 남기고 멈춥니다.

  1. 내부재고 설정 확인

    체인/벤더 그룹관리에서 Franchise 정보를 조회해, 재고 연동 API 항목이 '내부재고'로 설정되어 있는지 확인합니다.

    “체인/벤더 그룹관리에서 '내부재고'를 설정해주세요!” + URL

  2. key · code · secret 등록 확인

    같은 Franchise 정보에서 key, code, secret이 모두 등록되어 있는지 확인합니다.

    미등록 항목 안내 + URL

  3. key · code · secret 중복 확인

    같은 스테이징 안에서 key:code:secret 조합이 다른 프랜차이즈와 겹치지 않는 유니크한 값인지 확인합니다.

    중복 안내 + URL

  4. 토큰 생성

    key, code, secret을 조합하고 암호화 라이브러리로 암호화해 토큰을 생성합니다.

    자동 처리

  5. vendor code 확인

    벤더 관리에서 YGYvendorId의 기본 정보를 조회해, vendor code가 등록되어 있는지 확인합니다.

    “벤더 관리에서 'vendor code'를 입력해주세요!” + URL

  6. 재고 API 호출

    vendor code와 토큰, 상품코드와 수량으로 재고 입력 API를 호출합니다.

    성공 메시지 전송

- ISSUE

필요한 API가 없을 때,
있는 API로 풀었습니다.

구현 중에 만난 제약과 선택한 해결 방법, 그리고 그 방법이 가진 한계입니다.

ISSUESOLUTIONTRADE-OFF

중복 체크를 위한 API가 없음

같은 스테이징에 있는 프랜차이즈 목록 API를 전체 조회하고, '내부재고'로 설정된 프랜차이즈의 key:code:secret 조합값을 순차적으로 비교했습니다.

프랜차이즈가 늘어날수록 조회와 비교에 드는 시간이 길어질 수 있습니다.

- NOTIFY

실패는 고칠 곳과 함께,
성공은 짧게.

수행 결과는 비공개 QE 자동화 채널로 전송합니다. 실패 메시지에는 수정해야 할 백오피스 화면 링크를 함께 붙입니다.

FAIL · 사전 조건 미충족

체인/벤더 그룹관리에서 '내부재고'를 설정해주세요!
