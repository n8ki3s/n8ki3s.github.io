핀다 (FINDA) · AUTOMATION 01

Finda Automation

핀다 앱의 대출 신청 플로우 44개를 Android·iOS 실기기에서 자동으로 회귀 테스트하는 시스템을 만들고 운영합니다. 설계부터 구현, 운영까지 혼자 맡고 있습니다.

AT A GLANCE

01 · SCOPE

대출 4종, 플로우 44개를 돌립니다.

주택담보·신용·사업자·전세대출의 약 3,300개 스텝을 하나의 YAML로 두 OS에서 실행합니다.

02 · SPEED

6시간 걸리던 회귀를 줄였습니다.

OS별 수동 회귀에 약 6시간이 걸렸지만, 자동화한 뒤 Android는 77분, iOS는 177분이 걸립니다.

03 · RECOVERY

LLM은 실패한 스텝에만 씁니다.

스텝이 실패하면 LLM이 화면을 분석해 복구하고 그 스텝만 재시도합니다. LLM의 판정은 기록으로만 남깁니다.

- BACKGROUND

해석하는 자동화에서,
고정된 자동화로.

처음에는 Python과 Appium을 기반으로, 한국어 시나리오를 규칙 엔진과 LLM이 해석해 실행하도록 만들었습니다(2025.09~2026.04). 운영하면서 아래 문제가 드러났고, 오픈소스 Go 러너(maestro-runner)를 포크해 다시 구성했습니다.

  1. 실행할 때마다 해석이 달라짐

    같은 시나리오인데도 실행할 때마다 해석이 달라져서, 실패 원인을 추적하기 어려웠습니다.

    테스트를 YAML로 고정하고, 변환기는 txt2maestro로 분리

  2. 입력이 안 됐는데 성공으로 처리됨

    입력 필드에 값이 들어가지 않았는데도 드라이버가 성공으로 처리하는 경우가 있었습니다.

    드라이버 버그를 직접 수정

  3. 시나리오가 OS별로 나뉘기 시작함

    iOS와 Android의 차이 때문에 같은 플로우를 OS별로 따로 관리하게 됐습니다.

    OS 차이는 드라이버에서 처리하고 YAML은 하나만 유지

- CONTRIBUTION

러너를 고치고,
지표를 믿을 수 있게.

포크한 러너의 드라이버를 직접 수정하고, 실패 복구와 지표 집계, 운영 도구까지 만들었습니다.

01 · DRIVER FIX

드라이버 버그 수정

  • iOS에서 입력 필드에 포커스가 없는데도 입력 성공으로 처리되던 문제를 고쳤습니다.
  • 상대 셀렉터(below 등)가 기준 요소에서 먼 요소를 선택하던 문제를 고쳤습니다.

02 · ONE YAML

OS 공통 YAML 유지

  • OS 차이는 드라이버에서 처리하고, YAML은 하나만 유지하는 것을 원칙으로 정했습니다.
  • SMS 인증번호 자동입력 칩을 탭하는 동작을 Android·iOS 드라이버에 각각 구현했습니다.

03 · LLM RECOVERY

LLM 실패 복구

  • 스텝이 실패하면 Codex CLI로 화면을 분석해 복구한 뒤, 해당 스텝만 재시도합니다.
  • 플로우 전체에 시나리오 단위 라벨을 붙여 LLM이 화면의 의도를 알 수 있게 했습니다.
  • LLM의 판정은 실행 결과에 반영하지 않고 기록만 남깁니다.

04 · METRICS

테스트 지표 신뢰도 개선

  • 개발 중 실행과 정식 실행을 분리해, 통과율에는 정식 실행만 반영합니다.
  • 플로우 파일을 수정한 이후의 실행만 연속 통과 횟수에 집계합니다.
  • 중단된 실행은 실패와 따로 구분해 집계에서 제외합니다.

05 · OPERATION

운영 도구

  • 대시보드에서 스위트를 실행하고 진행 상황을 실시간으로 확인합니다.
  • 실행 잠금을 두어 같은 기기에서 두 실행이 동시에 돌지 않게 했습니다.
  • 테스트 계정 정보는 Vault에서 가져오고, 리포트와 LLM 프롬프트에서는 마스킹합니다.

- RECOVERY

복구할 수 있는 것과,
없는 것을 구분합니다.

실패 처리 단계를 거쳐 최종 통과한 플로우는 37건(iOS 25건, Android 12건)입니다. LLM 복구로 통과시킨 스텝 11건은 모두 iOS에서 '직장명*' 라벨이 '직장명'과 '*' 두 요소로 나뉘어 노출되는 OS 간 차이를, 셀렉터를 다시 검색해 해결한 경우였습니다.

RECOVERED · 복구 성공

OS 간 앵커 구현 방식이 다른 부분을 LLM이 화면으로 판단해 통과 처리했습니다.

tapOn: below:text="직장명*"
RECOVERED_BY_LLM
Element already focused, skipping tap
↳ recovered after 1 attempt(s)

#1 reselect (down) 1000ms        복구됨
'직장명'과 '*'가 별도 요소여서 '직장명*' 앵커를 찾지 못함.
화면에 보이는 '직장명 입력' 필드를 직접 선택.

FAILED · 복구 실패

앱이 정상적으로 실행되지 않아, LLM이 액션을 판단할 수 없으므로 실패로 처리했습니다.

assertVisible: text="비밀번호를"
ASSERTION
Element not visible: context deadline exceeded:
no such element
↳ LLM recovery tried 1 time(s), none succeeded

#1 none (up) 1000ms              실패
화면과 요소 목록에 '비밀번호를'이 없음.
로딩 인디케이터도 보이지 않아 복구 액션을 추측할 수 없음.
