와이즈버즈 (wisebirds) · AUTOMATION 05

Adwitt Test Automation

광고 솔루션 ADWITT에서 사용자가 반복하던 캠페인 생성·수정 동작을, 실제 화면의 컴포넌트를 조작하는 UI 테스트로 스크립트화했습니다. 캠페인 목적 13종을 모두 다루며, 배포 전후 기본 기능 테스트에 사용했습니다.

  • PYTHON
  • SELENIUM
  • CHROME WEBDRIVER
  • UI TESTING
  • SLACK API
  • 2017—2019
AT A GLANCE

01 · AUTO

모든 목적을 한 번에 돌립니다.

13종 목적의 캠페인을 차례로 생성합니다. 한 목적에서 실패해도 화면을 캡처하고 다음 목적으로 넘어갑니다.

02 · MANUAL

실패한 조합만 다시 봅니다.

목적과 소재를 지정해 캠페인 하나를 생성합니다. 주로 Auto에서 실패한 캠페인을 확인하고 검증하는 데 씁니다.

03 · REPORT

실패는 화면과 함께 보냅니다.

에러가 발생하면 에러 메시지와 캡처 이미지를 Slack 채널로 전송합니다.

- MODE

넓게 훑는 Auto,
좁게 파는 Manual.

전체 회귀와 실패 재현을 하나의 코드베이스에서 처리하도록 실행 방식을 두 가지로 나눴습니다.

AUTO MODEA

모든 목적별 캠페인 생성

TARGET
캠페인 리스트에 있는 13종 목적을 모두 생성합니다.
CREATIVE
Create·Confirm·Manage 단계에서 소재를 각각 1개씩 생성합니다. 소재 유형은 랜덤 함수로 골라 실행할 때마다 다르게 등록합니다.
ON FAIL
현재 화면을 캡처하고, 다음 목적의 캠페인 생성을 시도합니다.
cList = ["BA", "DAE", "DAI", "LG", "MAE", "MAI", "PL",
         "PPE", "PCS", "RC", "VV", "WC", "Wcon"]
MANUAL MODEM

지정한 캠페인 하나만 생성

TARGET
캠페인 목적 하나를 지정합니다.
CREATIVE
단계별로 등록할 소재 유형을 순서대로 지정합니다.
USE CASE
Auto에서 실패한 캠페인을 같은 조건으로 다시 생성해 원인을 확인하고 검증합니다.
m = "MAI"
execute = ['image', 'image', 'instaStory']

- STRUCTURE

역할별로 나눈,
여섯 개의 모듈.

Chrome WebDriver, Selenium, Python으로 구성했습니다. 설정, 실행, 캠페인 생성, 대기, 리포트, 알림을 각각 다른 모듈이 맡습니다.

Adwitt1.0.py

MAIN · 실행과 에러 처리

  • main 서버 정보를 설정하고 로그인한 뒤 auto 또는 manual을 실행합니다.
  • login 계정 정보를 입력합니다.
  • test_Campaign_auto 리스트에 있는 캠페인을 생성하고, 실패하면 screenShot을 실행합니다.
  • test_Campaign_manual 지정한 캠페인을 생성하고, 실패하면 screenShot을 실행합니다.

Campaign.py

CAMPAIGN · 단계별 생성 동작

  • campaignType 목적별 정보 리스트를 생성합니다.
  • campaignStructure 단계별로 추가할 소재 유형을 랜덤 리스트로 만듭니다.
  • campaign 타입, 앱, 컨버전을 선택합니다.
  • audience 기본 placement와 타기팅을 설정하고, 첫 소재가 InstaStory이면 placement를 바꿉니다.
  • creative_* image · video · multi · instaStory · catalog 소재를 등록합니다.
  • gridView Manage에서 최종 소재가 등록됐는지 확인합니다.
  • create 위 동작을 묶어 3회 반복하며 소재 유형별로 생성합니다.

Config.py

CONFIG · 실행 정보 로드

  • Config.ini 파일에서 로그인 정보, 광고 계정, 페이지, 애플리케이션 등을 불러옵니다.

T.py

WAIT · 화면 활성 대기

  • sleep 로딩 딤(Dim)이 해제될 때까지 기다립니다.
  • waitContent 지정한 컨텐츠가 화면에 노출될 때까지 ID 또는 XPATH로 기다립니다.

Report.py

REPORT · 화면 캡처

  • screenshot 날짜별 폴더를 만들고 현재 화면을 캡처해 저장합니다.

Slack.py

NOTIFY · 에러 전송

  • post_message 에러 메시지를 Slack 채널로 보냅니다.
  • post_image Report.py가 생성한 캡처 파일을 함께 보냅니다.
Config.ini→ Adwitt1.0.py→ Campaign.py⇄ T.py→ on fail → Report.py→ Slack.py

SOLUTION

2018.03.20
ISSUE
SOLUTION
동작하던 명령이 AttributeError: 'WebDriver' object has no attribute 'is_element_present', 'assertTrue' 에러를 내며 실패했습니다.
find_element_by_id, find_element_by_xpath로 대체했습니다.
ISSUE
SOLUTION
if 문으로 element 존재를 분기했지만, 찾지 못하면 else로 가지 않고 NoSuchElementException이 발생했습니다.
try / except로 예외를 처리했습니다.
WORK Create New - Brand Awareness 동작 코드를 작성했습니다. recommended Audience를 선택하고, 600×600 싱글 이미지를 찾아 소재로 추가하며, Confirm에서 multi 이미지 소재를 추가합니다.
2018.03.21
ISSUE
SOLUTION
오디언스 추가 레이어 팝업에서 location 항목이 화면에 보이지 않아 에러가 발생했습니다. send_keys(Keys.END)는 focus 에러가 났고, window.scrollTo는 팝업이 아닌 전체 창에 동작했습니다.
scrollIntoView()로 element가 화면에 보일 때까지 스크롤하도록 해결했습니다.
WORK Brand Awareness 동작 코드를 개선해 [+] 버튼으로 Create Audience를 추가하는 흐름을 넣었습니다.
driver.execute_script("arguments[0].scrollIntoView();", element)
2018.06.01
ISSUE
SOLUTION
셀렉트박스 리스트의 id에 페이지를 불러올 때마다 바뀌는 랜덤 값이 들어갔습니다.
xpath의 contains()로 고정된 부분만 매칭해 항목을 선택했습니다.
ISSUE
SOLUTION
Lead Generation 목적의 Multi 소재 UI에서는 서로 다른 이미지가 여러 장 필요했습니다.
이미지 검색을 반복하면서 이미 고른 위치를 건너뛰어 서로 다른 이미지를 선택했습니다.
driver.find_element_by_xpath("//*[@id='select2-pagelist-container']").click()
driver.find_element_by_xpath("//*[contains(@id,'{pageId}')]").click()
2018.06.12
ISSUE
SOLUTION
PCS-Catalog 목적의 Confirm과 Manage 단계에서 변수 레이어의 div 위치가 바뀌어 에러가 발생했습니다.
절대 경로 xpath 대신 css selector로 element를 찾도록 바꿨습니다.
# driver.find_element_by_xpath("/html/body/div[11]/ul/li[4]").click()
driver.find_element_by_css_selector("body > div.abcabc > ul > li:nth-child(4)").click()
2019.10.23
ISSUE
SOLUTION
