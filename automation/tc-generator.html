- BACKGROUND

추측으로 채운 TC를,
근거로 채운 TC로.

처음에는 Kiro IDE에서 PRD와 Figma를 분석해 TC를 만드는 방식으로 시작했습니다. 운영하면서 아래 문제가 드러났고, 규칙을 한 곳(SSOT)으로 모으고 사용자가 확정한 내용만 TC에 반영하는 구조로 다시 구성했습니다.

  1. 교차 검증에 시간이 오래 걸림

    PRD·Figma·Tech Spec을 사람이 하나씩 열어 교차 검증하다 보니 시간이 오래 걸리고 놓치는 항목이 생겼습니다.

    충돌·미정의 항목을 체크리스트로 확정

  2. 근거 없는 기대 결과

    "보통 이렇게 동작하겠지"라는 추측으로 기대 결과를 채워서, 리뷰 때마다 근거를 묻는 질문이 나왔습니다.

    근거 인정·불인정 기준을 정하고, TC 생성 후 셀프 체크를 강제

  3. 도구마다 다른 프롬프트

    AI 도구마다 규칙을 따로 설명해야 해서 Claude Code용, Kiro용 프롬프트가 따로 존재했습니다.

    규칙을 SSOT로 통합하고, 도구별 진입 파일은 포인터만 유지

  4. 이어받을 때마다 처음부터

    세션이 끊기거나 다른 사람이 이어받으면 어디까지 진행했는지 처음부터 다시 확인해야 했습니다.

    진행 상태를 meta.json 파일로 기록

- PIPELINE

티켓 하나에서,
등록된 TC까지.

중간에 확정 게이트를 두어, 이해충돌이 있으면 사용자가 확정하기 전까지 TC 생성 단계로 넘어가지 않습니다. 티켓 대신 PRD와 Figma를 직접 제공해도 같은 흐름으로 처리합니다.

  1. Jira Epic 생성

    Epic을 만들고 QA 요청 티켓을 Parent로 연결합니다.

    Jira REST API

  2. 입력 수집

    티켓에서 디자인닥, Figma, Tech Spec 링크를 자동으로 추출합니다.

    Confluence API · 링크 추출

  3. PRD 분석

    화면 정책, 비즈니스 규칙, 에러 정책을 정리합니다. 취소선은 폐기로, TBD는 미확정으로 처리합니다.

    prd-analysis-rules.md

  4. Figma 분석

    화면 프레임, 플로우차트, annotation, 핸드오프 노트를 분석합니다.

    Figma MCP

  5. Tech Spec 분석

    API 분기 조건과 에러 코드를 PRD·Figma와 대조합니다. Tech Spec이 제공된 경우에만 수행합니다.

    tech-spec-analysis-rules.md

  6. 이해충돌 검토 · 확정 게이트

    문서 간 충돌과 미정의 항목을 체크리스트 HTML로 만들고, 사용자가 확정하기 전까지 다음 단계로 진행하지 않습니다.

    GATE · 사용자 확정

  7. 통합 명세 · TC 생성

    확정된 내용으로 통합 명세를 만들고, TC를 md와 html로 생성합니다.

    test-case-rules.md

  8. 셀프 체크

    표준 커버리지 11종을 화면마다 대조한 결과를 파일로 출력해야 완료로 처리합니다.

    selfcheck.md

  9. 등록

    확정된 TC를 Google Sheets에 등록하고, 시트 링크를 Jira Epic에 등록합니다.

    Google Sheets API · Jira

- CONTRIBUTION

어떤 도구로 돌려도,
같은 기준의 TC.

에이전트가 임의로 판단하는 지점을 줄이고, 누가 어떤 도구로 실행해도 같은 결과가 나오도록 다섯 가지 장치를 만들었습니다.

01 · SSOT

멀티 AI 도구 지원

  • 규칙은 docs/ai-collaboration/policies/에 한 벌만 둡니다.
  • AGENTS.md, CLAUDE.md, .kiro/steering/은 규칙을 복제하지 않고 정책 문서를 가리키기만 합니다.
  • 규칙 하나를 고치면 Claude Code·Kiro·Codex에 동시에 반영됩니다.

02 · EVIDENCE

근거 기반 원칙과 체크리스트

  • 기대 결과에 넣을 수 있는 근거와 넣을 수 없는 근거를 명확히 나눴습니다.
  • 문서끼리 내용이 다르면 에이전트가 임의로 고르지 않고 체크리스트 HTML을 생성합니다.
  • PO·PM도 브라우저만 열면 "PRD 기준" / "Figma 기준" / "확인 필요"를 고르고 코멘트를 남길 수 있습니다.

03 · SELF CHECK

셀프 체크 강제

  • 표준 커버리지 11종을 화면마다 대조합니다.
  • 커버리지 매트릭스, 11종 대조, 확정 이력 대조, 회귀/영향도 대조의 4개 표를 모두 출력해야 완료로 처리합니다.
  • 명세에 동작 정의가 없으면 추측으로 채우지 않고 미정의 항목으로 올립니다.

04 · FEEDBACK → RULE

피드백을 규칙으로 승격

  • 리뷰 피드백은 TC 수정으로 끝내지 않고, 원인을 진단한 뒤 규칙으로 승격합니다.
  • 피드백 로그에 날짜·피처·원인·적용 규칙을 남기고, 13건을 모두 정책 문서에 반영했습니다.
  • 예: 분기 ON 케이스만 쓰고 OFF 회귀 TC를 누락한 건 → 셀프 체크에 "회귀/영향도 대조" 표를 필수로 추가했습니다.

05 · HANDOFF

세션 핸드오프와 산출물 고정

  • 피처 폴더마다 meta.json에 Jira Epic·스프레드시트 URL과 status·lastStep을 기록합니다.
  • 세션이 끊기거나 다른 AI 도구로 바꿔도 다시 묻지 않고 이어서 작업합니다.
  • 피처마다 산출물 5종과 meta.json을 한 세트로 고정했습니다.
